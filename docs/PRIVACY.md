# Privacy

Aava is a game for children, and it is built so that there is nothing to say
here — which is the point of the page.

## What the game collects

Nothing. There is no account, no sign-in, no email address, no advertising, no
analytics, no crash reporting and no telemetry of any kind. The game has no
server: there is nowhere for data to go and no one on the other end.

## What is stored, and where

Everything a child makes — their profile name, their valley, what they built,
what they are carrying, their coins — is written to the game's own private
storage on the device and nowhere else.

If Android's backup is switched on for the device, Android may copy that private
storage into the owner's own Google account as part of the system backup, and
restore it when they set up a new phone. That is a service of the operating
system, between the device owner and Google; the game neither sends it nor sees
it.

Saves stay on the device: the game keeps the save it replaced and, when a
child starts the valley again, a numbered copy of the old one, so a mistake can
be undone by a grown-up with the file. Uninstalling the game removes its data
from the device.

## Playing together

Two children can play in the same valley when their devices are on the same
local network — the same home Wi-Fi. The game finds nothing by itself: one child
shows a short code and the other taps it in, and that code is the last part of a
private network address, rebuilt on the joining device from its own network. A
device on another network cannot be reached at all. There is no lobby, no
matchmaking, no relay and no server; nothing about a session leaves the local
network.

What travels between the two devices is what one child is doing in the valley:
where they are standing, what they have just built, how a ball or a ride is
moving, and which version of the game each is running. It is not stored by
anyone. The Android permissions the game declares for this are internet,
network state and Wi-Fi state, because a local connection needs them; the game
itself contacts no internet service of any kind.

## Talking

The game has a *talk* button, and it is push-to-talk in the strict sense: the
microphone is started when the button is pressed and stopped when it is
released, so it is not running at any other time. Speech goes to the other
devices in the same local session and is never written down — no recording, no
buffering to disk, no history. A check in the build fails if the voice code so
much as learns how to open a file.

The microphone is used for nothing else. The only thing the game measures is
whether a packet is louder than a quiet room, so that silence is not sent;
nothing recognises, keeps or analyses what is said.

The microphone permission is asked for the first time a child presses the
button, not when the game opens, so the request has a reason a parent can see.

Talking can be switched off entirely in the menu, and the game remembers it.
With it off, the microphone cannot be started at all and the button is not
shown.

## Children

The game is made for children and asks them for nothing. It collects no personal
data, so there is nothing to consent to, nothing to delete and nothing to
export. If that ever changes, it will change here first.
